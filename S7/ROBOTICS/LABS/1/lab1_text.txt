1. What is ROS?
The Robot Operating System (ROS) is an open-source framework designed to help developers build
robust and complex robotic systems.
Despite its name, ROS is not a real operating system but rather a middleware that sits between
the underlaying operating system and the robot’s application code.
ROS provides ready-to-use tools, libraries, and drivers for robot control, perception, navigation,
and simulation. Developers can integrate sensors, actuators, and algorithms to create complete
robotic systems.
ROS 2 is the next generation of ROS. It was redesigned to improve communication, security,
scalability, and support for real-time robotic applications.
ROS 2 applications are organized into modular components called nodes. Nodes communicate
using topics, services, and actions.
The ROS graph represents the nodes in a ROS 2 system and the communication connections
between them.
For example, a mobile robot may contain:
• A camera driver node.
• A laser scanner node.
• A localization node.
• A navigation node.
• A motor controller node.
These nodes exchange information through ROS 2 communication mechanisms.

2. Why ROS?
ROS has become the de facto standard for building, testing, and deploying robotics software. It
is widely used in robotics education, research, and industrial development for several reasons.
• Ready to use: It provides tools, libraries, drivers, and reusable components.
• Flexible: It supports multiple programming languages, including Python and C++.
• Open source: Its software ecosystem encourages reuse, modification, and collaboration.
• Strong community: Supported by a large global network of developers and researchers.
• Modular architecture: Applications can be divided into independent nodes.
• Proven and reliable: Used in education, research, and real-world robots.
• Simulation support: ROS 2 can be integrated with robotic simulators and visualization
tools.
• Broad applicability: ROS is used in mobile robotics, industrial automation, aerial robotics,
and other fields.

3. Basic Concepts
This section introduces the main ROS 2 concepts and demonstrates how to inspect and interact
with a running ROS 2 system.
The ros2 command-line interface allows users to start nodes, inspect topics, call services, manage
parameters, and interact with other ROS 2 components.

3.1 Installing turtlesim
turtlesim is a lightweight simulator for learning ROS 2. It provides a simple environment for
practicing with nodes, topics, services, and actions before working with a real robot or a more
advanced simulator.
3.1.1 Setting up the environment
Open a terminal and source the ROS 2 Jazzy environment:
source /opt/ros/jazzy/setup.bash

This command configures the current terminal to use ROS 2 Jazzy.
3.1.2 Installing turtlesim
Execute the following commands:
sudo apt update
sudo apt install ros-jazzy-turtlesim

3.1.3 Verifying the installation
Check the available executables:
ros2 pkg executables turtlesim

3.2 Nodes
A node is a modular component of a ROS 2 application that performs a particular function.
For example, a node may control wheel motors, process camera images, publish laser scanner
measurements, or estimate the robot’s position.
A robotic system typically consists of several nodes working together.
Nodes communicate through topics, services, and actions. They can also expose parameters that
configure their behavior.
3.2.1 Running nodes with ros2 run
The general syntax is:
ros2 run <package_name> <executable_name>

For example:
ros2 run turtlesim turtlesim_node

Here, turtlesim is the package name, and turtlesim_node is the executable name.
3.2.2 Listing nodes
The command ros2 node list displays the names of currently running nodes.
Open a new terminal while turtlesim is still running in the other one, and enter:
ros2 node list

The output should include:
/turtlesim
/teleop_turtle

The exact output depends on the nodes currently running.

3.2.3 Remapping node names
ROS names without modifying the source code.
Remapping allows users to reassign default node properties, like node name, topic names, service
names, etc., to custom values.
Let’s reassign the name of our /turtlesim node. In a new terminal, run the following command:
ros2 run turtlesim turtlesim_node \
--ros-args --remap __node:=my_turtle

List the active nodes again:
ros2 node list

You should now see a node named /my_turtle in addition to the other running nodes.
3.2.4 Inspecting nodes
The command ros2 node info displays information about a node’s publishers, subscribers, services,
and actions.
ros2 node info <node_name>

To examine your latest node, /my_turtle, run the following command:
ros2 node info /my_turtlesim

Now try running the same command on the teleoperation node, and see how its connections differ
from /my_turtle.
ros2 node info /teleop_turtle

Compare the communication interfaces of both nodes.

3.3 Topics
Topics are communication channels through which ROS 2 nodes exchange messages.
ROS 2 topics use a publish/subscribe communication model. A publisher sends messages to a topic,
while subscribers receive messages from that topic.
A node can publish to several topics and subscribe to several other topics.
3.3.1 Listing topics
Running the ros2 topic list command in a new terminal will return a list of all the topics
currently active in the system:
/parameter_events
/rosout
/turtle1/cmd_vel
/turtle1/color_sensor
/turtle1/pose

To display topic names and their message types:
ros2 topic list -t

3.3.5 Publishing messages from the terminal
Now that you have the message structure, you can publish data to a topic directly from the
command line using:
ros2 topic pub <topic_name> <message_type> ’<arguments>’

The ’<args>’ argument is the actual data you’ll pass to the topic, in the structure you just
discovered in the previous section.
It’s important to note that this argument needs to be input in YAML syntax. Input the full
command like so:
ros2 topic pub --once /turtle1/cmd_vel \
geometry_msgs/msg/Twist \
"{linear: {x: 2.0, y: 0.0, z: 0.0}, \
angular: {x: 0.0, y: 0.0, z: 1.8}}"

You will see your turtle move. The –once option publishes one message and then exits.
The turtle (and commonly the real robots which it is meant to emulate) require a steady stream of
commands to operate continuously. So, to get the turtle to keep moving, you can run:
ros2 topic pub --rate 1 /turtle1/cmd_vel \
geometry_msgs/msg/Twist \
"{linear: {x: 2.0, y: 0.0, z: 0.0}, \
angular: {x: 0.0, y: 0.0, z: 1.8}}"

The difference here is the removal of the –once option and the addition of the –rate 1 option,
which tells ros2 topic pub to publish the command in a steady stream at 1 Hz.
Finally, you can run echo on the pose topic:
ros2 topic echo /turtle1/pose

You can see that the /turtlesim node is also publishing to the pose topic.
3.3.6 Measuring the publication rate
The command ros2 topic hz estimates the rate at which messages are received.
ros2 topic hz /turtle1/pose

The result depends on the simulator and the execution environment.
You can also measure the rate of velocity commands:
ros2 topic hz /turtle1/cmd_vel

3.4 Services
Services are another method of communication for nodes in the ROS graph.
A service is a request/response pattern where a client sends a request to a service server, which
processes the request and returns a response.
Unlike topics, which are generally used to stream data, services are suitable for operations that
require a response.

3.4.1 Listing services
Display the available services:
ros2 service list

The turtlesim simulator provides services such as:
/clear
/kill
/reset
/spawn
/turtle1/set_pen
/turtle1/teleport_absolute
/turtle1/teleport_relative

3.4.2 Inspecting a service type
Services have types that describe how the request and response data of a service is structured.
Service types are defined similarly to topic types, except service types have two parts : one message
for the request and another for the response.
To find out the type of a service, use the command:

3.4.3 Calling a service
You can call services from the command line, but first you need to know the structure of the input
arguments.
ros2 interface show <type_name>

From the results of ros2 service list -t, we know /spawn’s type is turtlesim/srv/Spawn. To
see the request and response arguments of the /spawn service, run the command:
ros2 interface show turtlesim/srv/Spawn

Which will return:
float32 x
float32 y
float32 theta
string name # Optional. A unique name will be created and returned if
this is empty
--string name

The information above the –- line tells us the arguments needed to call /spawn. x, y and theta
determine the 2D pose of the spawned turtle, and name is clearly optional.

The information below the line isn’t something you need to know in this case, but it can help you

Now that you know what a service type is, and how to find the structure of that type’s arguments,

ros2 service call <service_name> <service_type> <arguments>

ros2 service call /kill turtlesim/srv/Kill \

3.5 Parameters
A parameter is a named configuration value associated with a ROS 2 node.
Parameters can be used to configure a node’s behavior without modifying its source code.
For example, turtlesim has parameters that control its background color.
3.5.1 Listing parameters
To see the parameters belonging to your nodes, open a new terminal and enter the command:
ros2 param list /turtlesim

You will see the node namespaces, /teleop_turtle and /turtlesim, followed by each node’s
parameters.
The output includes parameters similar to:
background_b
background_g
background_r
use_sim_time

3.5.2 Reading a parameter
To display the type and current value of a parameter, use the command:
ros2 param get <node_name> <parameter_name>

Let’s find out the current value of /turtlesim’s parameter background_g:
ros2 param get /turtlesim background_g

Which will return the value:
Integer value is: 86

Now you know background_g holds an integer value. If you run the same command on background_r
and background_b, you will get the values 69 and 255, respectively.
3.5.3 Changing a parameter
To change a parameter’s value at runtime, use the command:
ros2 param set <node_name> <parameter_name> <value>

Let’s change /turtlesim’s background color:
ros2 param set /turtlesim background_r 150

The background of your turtlesim window should change colors.
Parameters can also be set when a node starts:
ros2 run turtlesim turtlesim_node \
--ros-args -p background_r:=255

Setting parameters with the set command will only change them in your current session, not
permanently. However, you can save your settings and reload them the next time you start a node.
3.5.4 Dumping parameters
You can view all of a node’s current parameter values by using the command:
ros2 param dump <node_name>

The command prints to the standard output (stdout) by default but you can also redirect the
parameter values into a file to save them for later:
ros2 param dump /turtlesim > turtlesim.yaml

You will find a new file in the current working directory your shell is running in. If you open this
file, you’ll see the current configuration of /turtlesim’s parameters.
Dumping parameters comes in handy if you want to reload the node with the same parameters in
the future.

3.5.5 Loading parameters
You can load parameters from a file to a currently running node using the command:
ros2 param load <node_name> <parameter_file>

To load the turtlesim.yaml file generated with ros2 param dump into /turtlesim node’s parameters, enter the command:
ros2 param load /turtlesim turtlesim.yaml

Note : Read-only parameters can only be modified at startup and not afterwards, that is why there
are some warnings for the “qos_overrides” parameters.
To start the same node using your saved parameter values, use:
ros2 run <package_name> <executable_name> --ros-args --params-file <file_name>

This is the same command you always use to start turtlesim, with the added flags –ros-args and
–params-file, followed by the file you want to load.
Stop your running turtlesim node, and try reloading it with your saved parameters, using:
ros2 run turtlesim turtlesim_node --ros-args --params-file turtlesim.yaml

The turtlesim window should appear as usual, but with the purple background you set earlier.

3.6 Actions
Actions are one of the communication mechanism in ROS 2 and are intended for long running
operations.
They are built on topics and services and they consist of three parts: a goal, feedback, and a result.
Actions are useful for tasks such as navigation, trajectory execution, and robot manipulation.

An action client sends a goal to an action server. The server can provide feedback while executing
the goal and eventually return a result.

4. Creating and Building ROS 2 Packages
4.1 Creating a Workspace
A ROS 2 workspace is a directory containing ROS 2 packages. Before using ROS 2, it is necessary
to source the ROS 2 installation environment.

ROS 2 also supports the use of overlays and underlays. An underlay is an existing workspace
that provides packages and dependencies, while an overlay is a secondary workspace where you can
develop or add packages without modifying the original installation.
Packages in an overlay take precedence over packages with the same name in the underlay. The
underlay must contain the dependencies required by the packages in the overlay.
Using overlays is recommended when working on a small number of packages, as it avoids rebuilding
an entire workspace during each development iteration.

5. Launching Nodes
Launch files allow you to start and configure multiple executables containing ROS 2 nodes simultaneously. Using the ros2 launch command, you can start an entire system, including its nodes and
configurations, from a single launch file.

5.1 Launching Multiple Turtlesim Nodes
Open a new terminal and execute:
ros2 launch turtlesim multisim.launch.py

If the launch file is available in your installation, this command starts two turtlesim nodes.
The launch file is written in Python and has the following structure:
from launch import LaunchDescription
from launch_ros.actions import Node
def generate_launch_description():
return LaunchDescription([
Node(
namespace=’turtlesim1’,
package=’turtlesim’,
executable=’turtlesim_node’,
output=’screen’
),
Node(
namespace=’turtlesim2’,
package=’turtlesim’,
executable=’turtlesim_node’,
output=’screen’
),
])

Open a second terminal and publish a velocity command to the first turtle:
ros2 topic pub /turtlesim1/turtle1/cmd_vel \
geometry_msgs/msg/Twist \
"{linear: {x: 2.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 1.8}}"

Open a third terminal and publish a velocity command to the second turtle:
ros2 topic pub /turtlesim2/turtle1/cmd_vel \
geometry_msgs/msg/Twist \
"{linear: {x: 2.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: -1.8}}"

Both commands continuously publish velocity messages by default. The first turtle moves forward
while turning in one direction, whereas the second moves forward while turning in the opposite
direction.

6. Recording and Playing Back Data
The ros2 bag command-line tool allows you to record messages published on ROS 2 topics and
save them for later analysis or playback.
Recorded data is stored in a bag directory containing metadata and the recorded data files. These
recordings can be replayed to reproduce experiments, analyze robot behavior, and share results
with others.
First, open a terminal and start the turtlesim node:
ros2 run turtlesim turtlesim_node

Open a second terminal and start the keyboard teleoperation node:
ros2 run turtlesim turtle_teleop_key

6.1 Recording Data with ros2 bag
Create a directory to store the recordings. Open another terminal and execute:
mkdir -p ~/bag_files
cd ~/bag_files

The ros2 bag tool records messages published on topics. In this example, the teleoperation node
publishes velocity commands on the /turtle1/cmd_vel topic.
To observe these messages, open another terminal and run:
ros2 topic echo /turtle1/cmd_vel

Use the arrow keys to move the turtle. You should see velocity messages displayed in the terminal
running ros2 topic echo.
Press Ctrl+C to stop the command.
6.1.1 Recording a Single Topic
The general syntax for recording messages published on a topic is:
ros2 bag record <topic_name>

Open a new terminal and navigate to the directory created earlier:
cd ~/bag_files

Start recording the velocity commands:
ros2 bag record /turtle1/cmd_vel

The terminal displays messages indicating that recording has started. The exact output depends
on your ROS 2 version and storage configuration.
For example, you may see messages indicating that the tool has opened a storage file, subscribed to
the selected topic, and started recording messages.
